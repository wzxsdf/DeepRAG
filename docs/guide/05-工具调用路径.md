# 工具调用路径（LangChain 1.0 create_agent）

> quick / agent 常态的 ReAct 工具闭环：LLM 自主决定调哪个工具、调几次、何时停，自己生成最终回答。
> 涉及 `src/agents/tools.py`（`@tool` 工具集 + `create_agent` + 中间件 + `run_react_agent`）。
> **LangChain 1.0 迁移**：原手写 function-calling 循环（`run_tool_agent` + `chat_message`）已重构为 `create_agent` + `AgentMiddleware`。

## 一、为什么需要工具

KB 检索覆盖私有文档，LLM 常识覆盖通用知识，但**实时/外部信息**（天气、时间、网页搜索、精确计算）两者都不可靠：

- "今天北京天气" → KB 没有，LLM 常识会编造（训练截止后数据）
- "123 × 456" → LLM 可能算错
- "最新的 X 框架" → 需联网

`tool_agent` 节点让 LLM 在 ReAct 循环里**自主调用工具**收集数据，再生成回答。quick 模式默认走此路径（LLM 自主决定是否查 KB / 调工具 / 纯常识答）。

## 二、LangChain 1.0 create_agent（取代手写循环）

**原方案**：`run_tool_agent` 手写 function-calling 循环（`chat_message(tools=)` + `_dispatch_tool` + `MAX_TOOL_STEPS`），配合 OpenAI 原生工具 dict schema。

**现方案**（LangChain 1.0）：`langchain.agents.create_agent` + `AgentMiddleware`，标准化 + 可插拔中间件。

```python
from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware

_react_agent = create_agent(
    model=get_gateway().chat_model("fast"),       # 经 ModelGateway 统一 LLM(阶段2)
    tools=REACT_AGENT_TOOLS,
    middleware=[SummarizationMiddleware(model=llm, ...), ToolAuditMiddleware()],
    system_prompt=TOOL_AGENT_PROMPT,              # 注意: 1.0 用 system_prompt(非 prompt)
)
```

> ⚠️ **LangChain 1.0 坑**：`create_agent` 参数是 `system_prompt`（不是旧文档的 `prompt`）；流式节点名是 **`"model"`**（不是 `"agent"`）——见 §5。

## 三、@tool 工具集（schema 自动从签名+docstring 生成）

`@tool` 装饰器取代手写 OpenAI dict schema，**schema 自动从函数签名 + docstring 推导**：

| 工具 | 功能 | 实现 |
|---|---|---|
| `search_kb_tool` | 知识库检索 | 经 `config.configurable` 注入 retriever，retrieve + rerank，返 chunk 摘要 |
| `weather_tool` | 实时天气 | Open-Meteo geocoding + forecast |
| `calc_tool` | 精确计算 | ast 白名单安全求值（禁 eval） |
| `web_search_tool` | 联网搜索 | Tavily API（需 key） |
| `time_tool` | 当前时间 | 东八区 datetime（无外部 API） |

```python
@tool
async def search_kb_tool(query: str, config: RunnableConfig) -> str:
    """在知识库检索与查询相关的文档片段。需要查找事实证据时调用。"""
    cfg = (config or {}).get("configurable", {})
    retriever = cfg.get("retriever")   # per-request 注入(不暴露给LLM)
    docs = await retriever.retrieve(query, RetrievalFilter(...), top_k=5)
    return "\n".join(f"- {d.content[:150]}" for d in await rerank(query, docs, top_n=3))
```

**per-request 上下文注入**：`search_kb_tool` 的 `retriever/tenant_id/kb_ids` 经 `config["configurable"]` 传入（`RunnableConfig` 参数不暴露给 LLM 的工具 schema），实现同一缓存 agent 服务多租户/多 KB。

**`REACT_AGENT_TOOLS = [search_kb_tool, weather_tool, calc_tool, web_search_tool, time_tool]`** —— 加新工具只改此列表（开放-封闭）。

## 四、中间件（AgentMiddleware）

`create_agent` 支持可插拔中间件，三个钩子（`before_model` / `modify_model_request` / `after_model`）：

| 中间件 | 来源 | 作用 |
|---|---|---|
| `SummarizationMiddleware` | LangChain 内置 | 长对话超 token 阈值自动汇总（保留最近 N 条），防 context 爆炸 |
| `ToolAuditMiddleware` | 自定义 | `after_model` 钩子审计每次 LLM 发起的 tool_call（记录日志，预留接 langfuse trace） |

```python
class ToolAuditMiddleware(AgentMiddleware):
    def after_model(self, state) -> dict | None:
        msgs = state.get("messages") or []
        for tc in (getattr(msgs[-1], "tool_calls", None) or []):
            log.info("tool_call", name=tc.get("name"), args=tc.get("args"))
        return None
```

## 五、get_react_agent（缓存 + per-request 注入）

```python
_react_agent = None
def get_react_agent():
    if _react_agent is None:
        _react_agent = create_agent(...)   # 全局单例
    return _react_agent
```

agent 全局缓存（model + tools + middleware 固定）；per-request 上下文（retriever/tenant_id/kb_ids）在调用时经 `config={"configurable": {...}}` 注入 `search_kb_tool`。

## 六、run_react_agent 流式映射（节点 = "model"）

`run_react_agent` 用 `astream(stream_mode=["messages", "updates"])` 流式，映射前端事件：

```python
async for mode, chunk in agent.astream({"messages": msgs},
        config={"configurable": configurable}, stream_mode=["messages", "updates"]):
    if mode == "messages":
        msg_chunk, metadata = chunk
        # ⚠️ 只 model 节点(LLM)的 token 做打字机, 排除 tools 节点 ToolMessage content
        if (metadata or {}).get("langgraph_node") == "model":
            if msg_chunk.content:
                final_text += msg_chunk.content
                writer({"tag": "token", "text": msg_chunk.content})
    elif mode == "updates":
        # tool 调用 → thought 事件(前端工具卡)
```

> ⚠️ **LangChain 1.0 关键坑**：messages 模式的 LLM token 来自 **`langgraph_node == "model"`** 节点（不是 `"agent"`）。早期写成 `"agent"` 导致 `final_text` 为空（用了工具但无文本输出）。同时须排除 tools 节点的 `ToolMessage.content`（工具返回值，不是回答）。

**source 判定**：调过工具 → `source=tool`；没调（纯常识）→ `source=fallback_unverified`。

## 七、各工具实现

### 7.1 天气（Open-Meteo，免 key）

两步：geocoding（城市→经纬度）+ forecast（经纬度→实时天气）。

**⚠️ 关键坑：geocoding 不支持中文**。实测中文"北京"返回空 results（英文索引），非网络问题。对策（ponytail）：`_CN2EN` 常用中文城市→英文映射（20 个）兜底 + 工具 description 要求 LLM 传英文/拼音。

容错：API 不可达 / 城市找不到 → 返回友好提示串（`"(天气服务暂不可用)"`），LLM 据实转告不编造。

### 7.2 计算（ast 白名单安全求值）

`calculate` 用 `ast.parse` + 白名单运算符/函数（sqrt/abs/log/sin...）求值，**禁 eval**，防 LLM 注入。除零/非法节点 → 错误提示串。

### 7.3 搜索（Tavily，需 key）+ 时间（本地）

`web_search`：Tavily API（无 key 返回提示串）。`time_tool`：纯本地东八区 datetime（无外部依赖）。

## 八、source 与前端

- `source=tool`（🔵 蓝徽章）：调了工具
- `source=fallback_unverified`（🟡 黄徽章）：没调工具，纯常识答
- 工具调用过程经 `thought` SSE 通道推送，前端思考过程面板按 `tag` 渲染工具卡

## 九、验证 + 扩展

`scripts/test_tool_calling.py`（5 用例全过）：天气（tool）/ 闲聊（non_kb）/ 常识（fallback_unverified）/ 计算（tool）/ 搜索（tool）。

**扩展**：加工具 = 写一个 `@tool` 函数 + 进 `REACT_AGENT_TOOLS`。**router、middleware、前端都不用改**（schema 自动生成，工具卡按 tag 通用渲染）。
