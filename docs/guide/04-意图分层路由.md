# 意图分层路由

> 把纯 RAG 升级为"会判断问题性质"的智能体。涉及 `src/agents/graph.py`（route/reply_direct/open_answer 节点）、`prompts.py`。

## 一、为什么需要意图路由

**问题**：纯 CRAG 系统对任何问题都走"检索→生成"。当用户闲聊（"你好"）或问常识（"什么是 RAG"）时，系统会检索知识库→找不到证据→**硬拒**："抱歉，未在知识库中找到相关证据，无法回答"。

体验极差——用户只是打个招呼，却被拒绝。

**目标**：让系统**先判断问题性质**，再决定走哪条路径：

- 知识库能答的 → 检索（可信引用）
- 闲聊 / 能力问询 → 直接友好回应（不打扰知识库）
- 通用常识 → 用 LLM 知识答（标注未验证）
- 实时信息 → 调用工具（详见 [05-工具调用路径](05-工具调用路径.md)）
- 越界 / 有害 → 礼貌拒绝

## 二、7 类意图分类

`_route_node` (`graph.py:90-118`) 用 `ROUTER_PROMPT` 将问题分为 7 类：

| 意图 | 含义 | 示例 | 路径 |
|---|---|---|---|
| `chitchat` | 闲聊 / 问候 / 致谢 / 情绪 | "你好"、"谢谢" | `reply_direct` |
| `capability` | 询问助手能力 / 身份 | "你能做什么"、"你是谁" | `reply_direct` |
| `kb_simple` | 知识库内单一事实，一次检索可答 | "X 是什么"、"X 用了什么技术" | `retrieve`（simple） |
| `kb_complex` | 知识库内多跳 / 跨文档对比 | "对比 A 和 B"、"X 如何依赖 Y" | `retrieve`（complex） |
| `open_qa` | 知识库外的通用常识 / 概念 | "什么是 RAG"、"Python 怎么读文件" | `open_answer` |
| `tool_call` | 需实时 / 外部信息，KB 与常识都不可靠 | 天气、股价、汇率、新闻 | `tool_agent` |
| `out_of_scope` | 越界 / 有害 / 无关指令 | 攻击脚本、医疗诊断 | `END`（refused） |

**LLM 输出 JSON**：`{"intent": "类别", "complexity": "simple/complex", "sub_queries": ["..."]}`（complexity 仅 kb_* 需判，sub_queries 仅 kb_complex 给 2-3 个）。

```
route ┬─ chitchat/capability → reply_direct  → END (non_kb)
      ├─ tool_call           → tool_agent    → END (tool)        [见 05]
      ├─ open_qa             → open_answer   → END (open_qa)
      ├─ out_of_scope        → END (refused)
      └─ kb_simple/kb_complex → retrieve → grade → generate → verify
```

## 三、规则快通道（省 ~4s LLM）

**`_classify_by_rule`** (`graph.py:78-87`)：用正则抓**100% 明显**的闲聊 / 能力问询，命中则跳过 route LLM，直进非检索路径。

```python
_CHITCHAT_RE = re.compile(r"你好|您好|在吗|谢谢|辛苦|早上好|...|hello|thanks", re.I)
_CAPABILITY_RE = re.compile(r"你(能|可以|会)(做|帮|干|回答).*|你是谁|你叫什么|支持什么|...", re.I)
```

**设计哲学**：**高 precision 低 recall**——只抓绝对不会错的，漏的走 LLM 兜底零误伤。`out_of_scope` 不用正则（不可靠），交 LLM 判。

> 💡 闲聊 / 能力问询命中快通道后**完全不触发 retrieve 节点**，不白检索，省一次 LLM 调用 + 检索延迟。

## 四、非检索路径

### 4.1 reply_direct（闲聊 / 能力问询）

**`_reply_direct_node`** (`graph.py:161-170`)

- 用 `CHITCHAT_PROMPT`（人设：DeepRAG 智能问答助手，友好简洁）
- 结合多轮历史（最近 3 轮）自然回应
- **不检索**，`source="non_kb"`
- 流式输出（`_stream_answer`）

### 4.2 open_answer（KB 外常识）

**`_open_answer_node`** (`graph.py:173-180`)

- `open_qa` 意图 → `OPEN_ANSWER_PROMPT`（基于通用常识答），`source="open_qa"`
- **安全护栏**：不答实时信息 / 医疗法律 / 隐私 / 违法（违反返 `REFUSED`）
- 不检索，不加载工具（省 token）

### 4.3 tool_agent（工具调用，详见 05）

`tool_call` 意图 → `tool_agent`，带外部工具获取实时信息。详见 [05-工具调用路径](05-工具调用路径.md)。

## 五、source 来源分级（6 键 5 色）

每个答案携带 `source` 字段，端到端透传到前端徽章，让用户一眼看出**答案可信度来源**：

| source | 含义 | 徽章色 | 图标 | 触发 |
|---|---|---|---|---|
| `kb_grounded` | 知识库·已引用 | 🟢 绿 | CheckCircle2 | verify 双通过 |
| `non_kb` | 非知识库 | ⚪ 灰 | MessageSquare | reply_direct |
| `open_qa` | 常识·未验证 | 🟡 黄 | Brain | open_answer（open_qa） |
| `fallback_unverified` | 常识·未验证 | 🟡 黄 | AlertCircle | verify 达上限降级 / tool_agent 未调工具 |
| `tool` | 工具·实时 | 🔵 蓝 | Wrench | tool_agent 调了工具 |
| `refused` | 无法回答 | 🔴 红 | AlertCircle | out_of_scope |

**流转路径**：`graph.py` → `query.py`（QueryResponse + done SSE）→ `chat.ts`（StreamDone）→ `Chat.tsx`（SOURCE_META 徽章）。

> 💡 这是 DeepRAG 相对通用 LLM 的差异化卖点：**透明分层**——用户知道答案来自知识库（可信）、常识（参考）、还是工具（实时），而非一个黑盒回答。

## 六、grade 软拒兜底

**关键改进（W3.5）**：`grade` 检索无相关证据时，不再硬拒 END，改为 `goto="tool_agent"` 软拒兜底。

```
grade 无证据 → tool_agent → (调工具 or 常识答) → END (tool / fallback_unverified)
```

这样即使 router 把问题判进 KB 但实际没证据，用户也能得到参考回答（而非冷冰冰的"无法回答"）。详见 [05-工具调用路径](05-工具调用路径.md) 的"grade 兜底"。

## 七、验证

`scripts/test_intent_routing.py`：
- "你好" / "能做什么" → non_kb，route→reply_direct **无 retrieve 节点**
- "什么是 HTTP 协议" → open_qa → open_answer 无 retrieve
- KB 问题 → kb_grounded 走完整 retrieve→grade→generate→verify
