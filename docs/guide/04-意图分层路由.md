# 模式驱动路由（取代意图分层）

> 把"LLM 预判意图"改为"用户显式选模式"，规避路由器无法预知 KB 内容的不可靠性。
> 涉及 `src/agents/graph.py`（`_entry_node`/`_classify_by_rule`/`_safety_rule`/`_judge_complex`）、`prompts.py`、`apps/api/query.py`、前端 `Chat.tsx`。
> 设计文档：`docs/superpowers/specs/2026-08-04-mode-routing-design.md`

## 一、为什么从"意图路由"改为"模式路由"

**原方案（W3.5 意图分层）**：用 LLM 把问题分为 7 类意图（chitchat / capability / kb_simple / kb_complex / open_qa / tool_call / out_of_scope），据此路由。

**致命缺陷**：路由器要预判"问题是否在知识库内"（`kb_simple` vs `open_qa`），但**路由器看不到 KB 内容**——它只能猜。猜错则用户得到错误路径（该检索的没检索，不该检索的白检索），且 `needs_planning` 预判同样不稳。

**重构方案（mode 路由）**：**把"判断问题性质"的权力交给用户**。用户显式选三种模式（严谨度/延迟权衡），系统按模式分发，**0 次意图 LLM 调用**。路由器不再猜测 KB 内容——用可靠的用户输入替代不可靠的 LLM 预测。

## 二、三种模式

| 模式 | 适用场景 | 链路 | 特点 |
|---|---|---|---|
| `quick`（默认） | 大部分日常问答 | `tool_agent`（ReAct + 工具，含 KB 检索工具） | 快；LLM 自主决定是否查 KB / 调工具（天气/时间/搜索/计算） |
| `kb` | 知识库严谨问答 | `retrieve → grade → generate → verify`（全套 CRAG 自纠） | 慢；带引用校验，答案 `kb_grounded` 可信 |
| `agent` | 复杂多源任务 | `_judge_complex` → `plan_agent`（规划+执行+综合）或 `tool_agent` | 复杂多步规划；简单则降级 ReAct |

用户在前端 Chat 页分段选择器选模式（localStorage 持久化），请求体带 `mode` 字段，初始状态写入 `AgentState.mode`。

## 三、入口节点 `_entry_node`（0 次意图 LLM）

`graph.py` 的 `_entry_node` 取代旧 `_route_node`，按"规则 → 安全 → 模式"三层分发：

```python
async def _entry_node(state) -> Command:
    question, mode = state["question"], state.get("mode", "quick")
    # ① 规则快通道: 明显闲聊/能力 → reply_direct(跨模式, 省 LLM)
    if _classify_by_rule(question) == "direct":
        return Command(update={"intent": "chitchat", "safety": "allow"}, goto="reply_direct")
    # ② 安全规则前置: 明显越界关键词 → END(0 LLM)
    if _safety_rule(question) == "refuse":
        return Command(update={"safety": "refuse", "source": "refused", ...}, goto=END)
    # ③ 按 mode 分发
    if mode == "kb":
        return Command(goto="retrieve")
    if mode == "agent":
        return Command(goto="plan_agent" if await _judge_complex(question) else "tool_agent")
    return Command(goto="tool_agent")  # quick 默认
```

**关键**：不再调用 LLM 做意图分类（省 ~4s + 消除不可靠性）。规则 + 用户 mode 直接决定路径。`AgentState` 新增 `mode` 字段，删除旧的 `route` / `needs_planning` / `complexity`。

## 四、规则快通道 + 安全前置

**`_classify_by_rule`**（高 precision 低 recall）：正则抓 100% 明显的闲聊/能力问询，命中则跨模式跳过分发直进 `reply_direct`（省一次 LLM）。

```python
_CHITCHAT_RE = re.compile(r"你好|您好|在吗|谢谢|辛苦|早上好|...|hello|thanks", re.I)
_CAPABILITY_RE = re.compile(r"你(能|可以|会)(做|帮|干|回答).*|你是谁|你叫什么|支持什么|...", re.I)
```

**`_safety_rule`**：正则抓明显越界关键词（攻击/黑客/漏洞利用/毒品/...），命中直接 END（`source=refused`），0 LLM。模糊越界交模式内系统提示护栏（`TOOL_AGENT_PROMPT` 等）。

> 💡 设计哲学：规则只抓绝对确定的（高 precision），漏的走模式内 LLM 兜底零误伤；越界靠正则前置 + 提示护栏双保险。

## 五、agent 模式的复杂度轻判 `_judge_complex`

agent 模式内，用一次轻量 LLM（`AGENT_COMPLEX_JUDGE_PROMPT`，**默认 false 强化**）判断是否需要规划：

- 多源 / 多步 → True → `plan_agent`（Plan-and-Execute：`chat_json` 规划 → 逐步执行 → 流式综合）
- 简单 → False → `tool_agent`（ReAct）

```python
async def _judge_complex(question) -> bool:
    try:
        res = await chat_json([{"role": "user", "content": AGENT_COMPLEX_JUDGE_PROMPT.format(question=question)}])
        return bool(res.get("complex", False))
    except Exception:
        return False  # 失败兜底False(走轻量ReAct)
```

**默认 false**：prompt 强调"除非明确多源多步，否则判 false"，避免过度规划。用户选 agent 模式即接受复杂任务的规划开销，但简单问题直接 ReAct 更快。

## 六、source 来源分级（6 键，前端徽章）

每个答案携带 `source` 字段，端到端透传到前端徽章，让用户一眼看出**答案可信度来源**：

| source | 含义 | 徽章色 | 触发 |
|---|---|---|---|
| `kb_grounded` | 知识库·已引用 | 🟢 绿 | kb 模式 verify 双通过（grounded + citations_valid） |
| `non_kb` | 非知识库 | ⚪ 灰 | reply_direct（闲聊/能力） |
| `tool` | 工具·实时 | 🔵 蓝 | tool_agent 调了工具（含 quick / agent 常态） |
| `planned` | 多源编排 | 🟣 紫 | plan_agent 多源综合 |
| `fallback_unverified` | 常识·未验证 | 🟡 黄 | verify 达上限降级 / tool_agent 未调工具 |
| `refused` | 无法回答 | 🔴 红 | safety 规则越界 |

**流转路径**：`graph.py`（节点设 source）→ `query.py`（QueryResponse + done SSE）→ `chat.ts`（StreamDone）→ `Chat.tsx`（SOURCE_META 徽章）。

> 💡 透明分层是 DeepRAG 相对通用 LLM 的差异化卖点：用户知道答案来自知识库（可信）/ 工具（实时）/ 编排（多源）/ 常识（参考），而非一个黑盒回答。

## 七、与旧意图路由的关系

mode 路由**取代**意图分层（7 类互斥 intent → 3 个正交 mode）。已删除：

- `ROUTER_PROMPT` / `OPEN_ANSWER_PROMPT`（意图分类 + 常识答）
- `open_answer` 节点、`route` 节点
- `AgentState.route` / `needs_planning` / `complexity` 字段

旧意图的覆盖方式：
- 闲聊 / 能力 → 规则快通道 + `reply_direct`（跨模式）
- 常识 → `tool_agent`（LLM 自主，不调工具即常识答，`source=fallback_unverified`）
- 越界 → `_safety_rule` 正则前置
- 工具 / KB → 用户选 quick（含工具+KB）/ kb（纯 CRAG）

## 八、grade 软拒兜底（kb 模式）

kb 模式 `grade` 检索无相关证据时，**不硬拒**，改为 `goto="tool_agent"` 软拒兜底：

```
grade 无证据 → tool_agent → (调工具 or 常识答) → END (tool / fallback_unverified)
```

即使 KB 没证据，用户也能得到参考回答（而非冷冰冰的"无法回答"）。

## 九、验证

`scripts/test_modes.py`（7 用例全过）：

| 用例 | 期望 |
|---|---|
| quick·工具（天气） | `source=tool`，调工具 |
| quick·带KB事实 | LLM 自主选择是否查 KB |
| **kb·CRAG** | `source=kb_grounded`，走完整 retrieve→grade→generate→verify |
| agent·工具 | `source=tool`，ReAct |
| agent·多源 | `judge_complex` 触发 plan（或简单降级 ReAct） |
| 闲聊·直答 | `source=non_kb`，规则快通道 |
| 越界·拒绝 | `source=refused`，safety 前置 |
